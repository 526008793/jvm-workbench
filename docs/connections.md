# SSH 与 JumpServer 接入

## 当前状态

0.2.0 已实现密码/私钥 SSH、主机指纹确认、keyboard-interactive/MFA 及 xterm 内嵌终端；凭据仅用于当前连接，不写入配置。当前已用本地隔离 SSH 服务验证，尚未与公司 JumpServer 真实版本联调。

## 直连 SSH

配置主机、端口、用户名，连接时输入密码或通过原生文件选择器选择私钥及必要的口令。渲染层只持有临时私钥引用，文件内容由主进程读取。主机身份首次确认后记录，身份变化必须明确处理，不能关闭验证以绕过连接失败。

短命令和持续日志使用独立通道。工具不能假定远程具有 bash、curl、jps 或其他辅助程序，需按操作需求确认能力。

## JumpServer

适配 SSH 登录后出现资产菜单的部署，认证可能使用 keyboard-interactive 和 MFA。当前流程：

```text
连接 SSH
→ 响应实际认证挑战
→ 等待资产菜单
→ 搜索并确认选定资产
→ 处理可能的账号选择
→ 确认目标服务器会话
→ 执行 Docker/Arthas 操作
```

认证挑战应按服务器真实提示展示；不能把某个终端客户端的 OTP 文案当成固定服务器协议。OTP 只用于当前认证，不保存或自动重放。

资产显示序号随查询、排序和分页变化，不是永久主键。应保存可唯一确认的资产身份，在当前会话定位目标。资产不唯一、目标变化或选机失败时不能继续执行命令。

当前不自动解析菜单或使用资产序号选机，assetName 仅为人工选择的提示。目标选好后点击确认，通过带随机标记的 shell 输出获取 hostname；菜单回显不能当成执行成功。之后任何人工终端输入都会取消自动操作就绪状态，需再次确认目标，以免人工跳回菜单后误执行。

## 并发与前台命令

一个项目窗口可以管理多个服务器会话，多项目窗口也可同时运行。但这不代表一个 SSH 连接必然支持多个目标，也不代表一次 MFA 可以验证所有连接。

同一前台 shell 跟随日志时无法直接再输入另一个诊断命令。直连 SSH 使用独立 exec 通道，终端与日志可并行。JumpServer 当前在已选目标的同一 shell 上分帧执行 Docker，一次只运行一个操作；读取日志期间终端只读，其他命令明确返回通道占用。不同目标配置使用各自连接，可能分别要求 MFA。

只为当前查看的服务和明确运行的任务建立所需通道，避免启动 APP 时自动订阅全部授权资产。

## 第一轮验证清单

| 项目     | 需要记录的结论                          |
| -------- | --------------------------------------- |
| 认证     | 密码/私钥/交互挑战、MFA 触发时机        |
| 选机     | 唯一定位方法、账号选择、分页行为        |
| 并发     | 同连接多通道或多连接、是否再次 MFA      |
| 命令     | exec、PTY、命令中断、退出后目标状态     |
| Docker   | ps/logs/exec 与工具包写入权限           |
| 文件传输 | 实际允许的上传方式与目标目录            |
| 转发     | 是否允许，以及容器内 agent 是否确实可达 |

对配置为 JumpServer 的服务器，目标访问继续经过堡垒机。直连 SSH 使用明确的独立服务器配置，不将其作为堡垒机失败时的自动绕过路径。

## 权限边界

读取日志不代表可执行容器命令或 attach JVM。权限失败应展示具体操作及原因，不自动切换 root 或增加服务器权限。首轮验证使用专门测试目标，不自动连接任何生产资产。

## 本机主机信任

首次连接展示 SHA-256 指纹，确认后写入 userData/known-hosts.json。指纹变化会直接拒绝连接，不弹出忽略验证的捷径。真实轮换密钥时，先由所有者独立核实指纹，再维护本地信任记录；应用不会自动覆盖。

连接由工作区所有，不跨窗口共享认证。关闭、重载或渲染进程异常时清理本工作区的连接、私钥引用和日志订阅，其他窗口保持独立。SSH keepalive 不能替代远端任务状态确认。
