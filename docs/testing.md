# 验证计划

## 当前仓库检查

`pnpm check` 执行格式、Markdown 和本地相对文件链接检查。CI 在 Linux/Node.js 22 上运行相同命令；这不等于 APP、macOS 打包或远程服务器兼容测试。

## 接入验证优先

在专门测试目标上记录平台、版本、认证方式、镜像、Java 版本、执行结果和限制，不记录秘密。分别验证直连 SSH 和 JumpServer，不以一种模式成功推断另一种也可用。

| 场景           | 验证标准                                   |
| -------------- | ------------------------------------------ |
| SSH 密码和私钥 | 正确认证，失败原因清晰，不降低主机身份验证 |
| JumpServer MFA | 正确响应动态挑战，失败/取消不继续选机      |
| 资产选择       | 重名、分页、账号选择和目标变化时不误连接   |
| 并发           | 记录实际允许的通道/连接以及重复 MFA 行为   |
| Docker 权限    | ps/logs 可用性与 exec/attach 分别确认      |
| 包分发         | 允许的传输方式、校验和、容器内路径和权限   |
| 日志与诊断并行 | 不在同一前台终端混发命令，不串输出         |

## 首期行为验收

| 场景           | 验证标准                                       |
| -------------- | ---------------------------------------------- |
| 两项目窗口     | 一个直连，一个 JumpServer，同时工作            |
| 同名服务或容器 | 不跨项目混淆目标、结果或凭据                   |
| 同服务双节点   | 日志合并带来源，诊断分别显示状态               |
| 日志量持续增加 | 内存与推送有界，界面仍可操作                   |
| 方法候选       | 展示类、签名和 ClassLoader，类未加载有明确提示 |
| 无流量         | 不把等待调用当失败或任务完成                   |
| 部分失败       | 独立展示失败节点和成功节点                     |
| 容器重启/重建  | 重新核对身份，不延用旧 JVM 会话                |
| 停止与超时     | 只中断当前任务，区分请求停止与已确认停止       |
| 断线重连       | 不盲目重复提交诊断，远端状态核对后更新         |
| 关闭工作区     | 只清理该窗口任务，不影响其他工作区             |
| APP 被强杀     | 验证远端实际状态，不宣称本地计时器仍有效       |

## 自动化测试方向

实现相关模块时再加入有业务价值的测试：认证/资产状态机用脱敏交互样本，任务管理覆盖多窗口归属和重复提交，日志处理覆盖分块、多行堆栈及实例来源。测试公共行为，不为简单取值和文案建立重复实现的测试。

真实 SSH、Docker 和 Arthas 集成测试需要显式准备的隔离环境，不在仓库 CI 自动连接生产服务器。Mac 应用冒烟和签名验证在实际构建流程加入后执行。
