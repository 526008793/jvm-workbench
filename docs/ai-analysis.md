# 独立 AI 配置与源码分析

0.3.17左侧“服务器配置”下新增独立“AI 配置”页。方法诊断不再嵌入模型表单；不接AI时仍显示本地建议，明确标注为本地规则生成。

## 配置模型与测试

进入“AI 配置”，填写模型服务Base URL或完整Chat Completions地址、模型名和可选API Key，保存后点击“测试连通性”。支持OpenAI兼容 `POST /chat/completions`，本地无鉴权服务可不填Key。不支持厂商独有签名协议或非Chat Completions端点。

未启用AI也可主动测试已保存配置，测试仅发送最小文本，不读取业务源码，不会因此开启自动分析。Key使用Electron safeStorage加密，不返回页面明文；更换API地址需重新填写或清除原Key。配置按项目独立保存，不改服务器版本或断开SSH。

自动源码分析仍须明确勾选，只处理新完成的深入诊断，不重跑历史、不因切换菜单发送代码。失败/关闭/取消AI会保留本地建议；关闭后默认回到本地结果，即使任务已有AI报告。

## 三步诊断

1. 方法诊断 → “接入 JVM”：连接并确认目标服务器，发现JVM并接入Arthas。连接就绪后上方服务器面板自动收起，可手动展开终端操作。
2. “方法诊断”：搜索和选择入口，启动诊断后触发一次业务。接入成功自动进入本区，切换AI配置页保留选择、参数和任务。
3. “诊断结果”：执行后自动进入结果区，直接查看慢点与本地建议，按需查看运行源码或启用AI分析。返回参数不需要在长页面滚动。

## 源码来源

新配置默认“Arthas 运行源码（反编译）”。可在AI配置中切换来源。0.3.16已有配置没有来源字段时沿用本地来源，避免静默改变原有自动分析行为。

运行源码通过任务原agent/JVM调用sm确认方法的真实ClassLoader，再执行jad。入口加载器与任务快照核对，不把线程上下文或调用方加载器套给其他类；多个加载器不猜。按入口业务命名空间提取采样涉及的方法，同一类/加载器只反编译一次，再提取方法片段。不会再次执行导出或改写业务实现；官方jad需要在远端写反编译临时class文件，容器需具备相关写权限，读取本身有反编译开销。

结果按任务缓存，重复查看/AI分析复用快照，记录容器、PID和读取时间。已缓存时断线仍可查看原任务源码；未缓存时必须连接原容器/JVM，容器重建后不会拿新JVM的代码解释旧任务。采样后若有热更新，读取到的是读取时版本，不能保证与采样瞬间字节码完全一致。

反编译不保证还原原始注释、变量名和行号。界面和模型输入区分“反编译依据”，片段行号只是反编译输出位置；不会假装已获得Mapper XML或数据库执行计划。源码查看不需要启用AI，也不会调用模型。

选择“本地源码”时，可关联与部署版本一致的Java项目根目录，提取真实方法及直接Mapper XML和同namespace include。重复类、行号不匹配和未展开片段会提示；分析后核对文件SHA256。忽略生成/测试目录和软链接，不读取YAML、环境配置或私钥，不执行源码或SQL。

## AI 分析与边界

AI分析会发送所选来源的相关方法与采样路径到配置服务。可以先查看将分析的源码。结果显示模型、生成时间、建议及实际提供的源码引用，区分代码可见事实和待验证的运行原因；引用不存在、格式不符或本地源码中途改动时拒绝结果。

采样比例不是精确方法耗时，RUNNABLE不等于CPU热点；数据库网络栈不直接证明慢SQL或缺索引。反编译来源缺少SQL时，模型必须保留不确定性。没有AI时的建议依然是本地规则，查看运行源码不意味着本地规则已完成语义分析。

可取消AI请求，关闭或重载工作区会中止所属请求。请求最长180秒，不自动重试；错误只输出安全状态，不回传服务原始正文。模型不能保证最终根因或建议正确，需结合实际部署版本、数据规模和运行指标核对。

接口参考：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/)。实际支持情况以所配置兼容服务为准。
