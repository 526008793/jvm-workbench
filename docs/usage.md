# 使用流程与当前可用内容

## 当前可用内容

0.3.20支持项目工作区、多服务器日志、单次请求深入诊断、运行源码查看及可选AI分析。服务器配置默认优先，日志页独立显示，SERVICES可编辑/删除。

## 启动

安装方法见[Mac与Windows安装使用](installation.md)。开发时执行`pnpm dev`，或先`pnpm build`再`pnpm start`；维护者在Mac执行`pnpm package:mac`，在Windows执行`pnpm package:win`。Windows实机运行尚未验收。

## 服务器与日志流程

1. 新建项目/环境，在服务器配置中填写地址、端口、用户和 SSH/JumpServer 类型。
2. 在连接面板点击服务器“连接”，输入本次密码或选择私钥。JumpServer 默认先输入登录密码，后续再按提示完成 MFA；仅交互认证取决于服务端是否支持。
3. 首次连接核对并确认 SHA-256 主机指纹，根据实际挑战输入 MFA。
4. JumpServer 在终端完成选机后点击“确认已进入目标服务器”，核对显示的 hostname；人工输入后需要重新确认。
5. 发现容器并关联到当前服务，或通过编辑服务配置容器映射。
6. 选定实例和日志范围开始订阅，使用关键词筛选、暂停显示、停止全部或单个实例。
7. 同一堡垒机账号的另一目标服务器配置出现“复用登录”时，点击可沿用已认证连接，在新终端选机并确认，不需重复输入密码/MFA（需堡垒机允许多PTY）。
8. 打开其他项目独立工作；关闭或重载当前工作区会释放其连接和订阅。

连接弹窗可勾选“在此设备上记住密码”，仅在成功认证后加密保存。下次输入框提示“已记住密码”时可直接连接；输入新密码可在成功认证后替换。点“忘记密码”立即清除，取消勾选后连接也会清除保存记录。私钥口令和动态验证码不保存。JumpServer 每个目标 shell 同时只支持一个 Docker 操作，读取日志时终端只读；需要其他操作时先停止日志。

## 服务器配置与服务列表

0.3.19菜单依次为服务器配置、服务日志、方法诊断、AI配置。新打开项目默认进入服务器配置，在此填写并建立连接、完成目标选机及容器发现，再切换日志或诊断。已打开项目重新唤起时保留当前页面。服务日志页只显示日志操作和输出，点击“开始日志”由APP自动运行，无需复制命令到终端。

SERVICES列表每行可直接编辑服务名称/容器映射或删除服务；删除当前项会切换剩余服务，删除最后一项显示空状态。日志页不再展示服务器连接与当前环境概览，方法诊断仍可展开接入连接面板。切换菜单不会断开连接或停止后台日志。

## 首页与最近项目

打开项目后，项目首页自动隐藏。点击左侧项目卡片“项目工作区”或顶部“项目管理”可再次显示首页；选择项目后首页继续隐藏，已经打开的项目复用原工作区，其他项目窗口保持运行。

点击Dock的APP图标或再次启动APP时，优先恢复最近聚焦的现有项目窗口，最小化窗口会恢复；如果所有工作区都关闭了，则重新打开最近选择的项目。完全退出后重启也恢复最近打开项目；首次启动、没有有效记录或该项目已删除时显示首页。仅恢复项目窗口，不自动恢复SSH连接、日志订阅或诊断任务。

## 同时查看不同服务器的服务日志

1. 为订单、商品服务器分别建一条目标服务器配置，名称例如“订单服务器”“商品服务器”。经同一JumpServer时地址/端口/账号可以相同。
2. 第一条正常登录并选到订单目标，确认hostname；第二条用“复用登录”打开独立终端，选到商品目标并确认。保持两个终端各自在对应服务器，不退出旧目标来切换。
3. 左侧创建mall-order、mall-goods服务，各自只关联正确目标连接上的容器。关联只保存映射，不会把退出的目标会话保留下来。
4. 分别选择服务并点击开始日志，切换服务后原日志继续在后台运行。
5. 未合并时只能单选一个实例；勾选“合并查看本环境服务日志”后可多选实例，并同屏查看不同服务的输出，每条记录包含服务、服务器和容器来源。关闭合并只看当前所选实例，其他后台任务继续。
6. 普通视图的停止/清空仅作用所选实例；合并视图提供“停止全部服务日志”，也可停止单个实例。切换环境会停止旧环境的日志。

日志范围可选只看新日志、最近N行、最近5分钟到24小时，或自定义开始/结束时间。日期时间按本机时区选择；结束时间不填则持续跟随，填写后查询固定时间段并自动结束。修改时间后重新开始所选实例日志生效。发现容器后可关闭列表，需要时再次展开；服务映射可从侧栏或顶部编辑服务，侧栏也可直接删除服务。

一条前台终端不能同时停留在两台服务器。一次堡垒机登录与多个目标终端是两个层次；复用登录仍要求实际JumpServer支持多个PTY。

SQL多行和异常堆栈按Java应用日志头组装为一条记录，关键词匹配任一续行会展示完整记录。Docker时间精度不决定业务记录的拆分。终端内滚动只影响历史内容，末行与光标按实际可用高度适配。

## Arthas

1. 在已连接服务器的服务中进入方法诊断，选择实例，点击“发现 JVM”，选择真实 PID。
2. 填写容器内工具包目录和 HTTP 端口，点击“接入 Arthas”。已有完整 Arthas 4.0.5 包或 arthas-boot.jar 会直接复用；缺失时从 Maven Central 下载官方可执行启动 JAR并校验 SHA-256，由启动器使用Java准备固定4.0.5版本依赖，无需unzip或JDK jar命令。默认目录为 /tmp/tracelogdock-arthas-4.0.5；首次准备依赖需要官方Arthas站点/Maven Central的HTTPS出网和目录写权限，界面显示准备阶段。自动下载JAR另需curl、sha256sum及常见shell工具；也可手动把同版本arthas-boot.jar放入所填目录。
3. 填写业务包名和方法名，或 `完整类名#方法名`，搜索已加载方法；选择类、签名和 ClassLoader 对应候选。
4. 选择模板、次数和最长运行秒数，预览后执行。候选签名不限制重载增强，实际命令匹配同 ClassLoader 下此名称的所有重载。
5. 每个实例分别执行并查看任务原始结果，点击“停止此诊断”只中断对应会话；超时也请求中断，未确认则显示未知。

慢调用结果自动显示耗时表。点击最慢调用旁的“继续诊断”，APP会回到原任务JVM搜索方法、填入下一步参数并定位输入区；唯一具体候选自动选中，有重载/多个ClassLoader或接口实现时先选择候选，再点击执行。此操作保留当前采集设置并由你触发下一次业务调用。新任务在前、旧任务和原始JSON可折叠。

容器需要 sh、awk、readlink、curl、Linux /proc 及可 attach 的 Java 环境。HTTP 只绑定容器 loopback，由容器内 curl 调用，不映射公网端口。应用关闭或断线后不能保证远端已经停止。实际镜像和 JumpServer 仍需授权测试环境验证，详见[接入前提](arthas.md)。

## 当前配置删除行为

删除项目有原生确认，会关闭其工作区，只删除本地项目配置。服务器被实例引用时须先调整服务配置；环境仅能在没有服务和服务器时删除，项目至少保留一个环境。

## 日志与诊断的区别

日志查看复用 Docker 现有输出及其保留范围；Arthas 观察启动监控之后发生的方法调用。历史日志不能自动还原当时未采集的方法参数或耗时树。

## 日志任务状态

| 情况         | 预期表现                             |
| ------------ | ------------------------------------ |
| 某实例无流量 | 增强完成后显示等待调用               |
| 其他节点命中 | 标记具体实例和服务器                 |
| 容器已重建   | 核对新身份，不继续使用旧诊断会话     |
| 部分节点失败 | 分别展示失败原因和其他节点结果       |
| SSH 断线     | 显示连接及远端任务状态未知，重连核对 |
| 用户停止     | 仅中断本任务，确认后显示已停止       |
| 关闭项目窗口 | 清理所属订阅与任务，保留其他窗口连接 |

## 所需条件

参见[连接说明](connections.md)与[Arthas 接入](arthas.md)。APP 不应自动扩大服务器权限，也不能假定日志权限等于诊断权限。

## 一次请求观察多层方法

1. 在方法诊断中搜索并选择最外层入口，例如Controller原始导出方法，点击“多层追踪”。
2. 填入要同时追踪的类和方法名；搜索Service/Assembler候选后可“加入当前候选”，入口仍保持原Controller。用“列出当前类方法”勾选doAssemble、fillGoodsList等私有辅助方法，也可手动填写已知方法名。
3. 点击“核对追踪范围”，检查实际类、方法、重载和ClassLoader；范围改变后重新核对。
4. 点击执行，等待增强完成，再触发一次导出，完成后查看同一任务中的多层耗时。多层默认次数1、最长300秒，不按#cost过滤。

只有明确范围内的方法会被增强；不要把入口更上层的方法加入范围，需要扩大到更上层时先设置新的最外层入口。

## 长请求只执行一次的深入追踪

0.3.14默认使用“深入追踪（单次请求）”。接入JVM后搜索并选择Controller等同步入口，点击执行，等待“增强完成，等待调用”后触发一次导出。无需填写Service、Assembler等下游类。请求执行中即可查看业务采样排行、完整路径、源码行和等待线索；入口退出后自动停止。最长时间默认600秒，包含等待业务的时间，可在执行前调整。

观察首个进入的同名入口调用（含重载），并发时核对实际线程。目标采样间隔默认1秒，HTTP长轮询与SSH会延长实际间隔，结果显示实际平均值。采样有开销，会漏过短暂方法，比例不是精确方法耗时；不自动跟踪异步子线程或远端服务内部，等待线索还需结合对应系统证据确认最终根因。需要已知方法的精确计时时可切换原“慢调用”或“多层追踪”。

## 简明诊断结论

0.3.15深入诊断默认只展示优先排查的方法、源码/调用位置、发现和优化建议。同方法的重复栈与行号变化合并，不重复列出全部父方法。建议根据数据库网络、连接池、锁、远端IO、休眠、文件IO或运行路径等实际证据生成；没有源码/SQL执行计划时不会直接断言缺索引或代码循环查询，改动建议明确使用条件。

采样表、线程信息和完整栈默认折叠到“查看诊断依据”，原始结果保持折叠。执行中仅显示正在诊断；无有效业务位置时不编造慢点。仅一个样本标记初步线索，不完整结果标记部分证据；出现次数不作为精确耗时。

## 可选源码AI分析

未配置AI时继续使用本地建议。0.3.17可在左侧进入独立“AI 配置”，选择Arthas运行源码或对应版本本地源码，配置兼容服务地址、模型名及可选密钥。保存后可测试连接，诊断结束后点击“AI 源码分析”；自动发送源码分析须明确勾选。失败或取消仍保留本地结果，详见[源码与AI分析](ai-analysis.md)。

## 分区诊断与运行源码

0.3.17方法诊断按“接入 JVM／方法诊断／诊断结果”切换，接入和执行后自动进入下一阶段，已就绪连接收起，模型表单只在左侧AI配置页。结果中的“查看运行源码”从原JVM使用Arthas jad读取方法，可在不启用AI时使用；AI读取相同来源，运行源码按原任务缓存，不再次触发业务。反编译无法保证原始行号或Mapper XML，详情见[源码分析](ai-analysis.md)。
