# 使用流程与当前可用内容

## 现在可以做什么

可以阅读架构、评审需求和运行文档检查。当前没有可运行 APP、下载链接或自动连接功能。

## 计划中的操作流程

1. 创建项目及环境，例如 Project Alpha / staging。
2. 为服务器选择直连 SSH 或 JumpServer 配置，录入所需认证引用。
3. 在 APP 内完成必要的主机身份确认和 MFA。
4. 从项目服务器发现 Docker 容器，确认服务归组。
5. 点击服务，选择全部或部分实例，打开日志模式和筛选。
6. 输入方法名，确认候选并选择慢调用、参数或异常等诊断。
7. 查看各实例状态及结果，通过任务栏停止当前任务。
8. 打开另一个项目工作区，并排查看；前一个窗口的视图和任务保持独立。

这些是目标交互，不是当前版本已支持操作的承诺。

## 日志与诊断的区别

日志查看复用 Docker 现有输出及其保留范围；Arthas 观察启动监控之后发生的方法调用。历史日志不能自动还原当时未采集的方法参数或耗时树。

## 异常情况如何呈现

| 情况         | 预期表现                             |
| ------------ | ------------------------------------ |
| 某实例无流量 | 增强完成后显示等待调用               |
| 其他节点命中 | 标记具体实例和服务器                 |
| 容器已重建   | 核对新身份，不继续使用旧诊断会话     |
| 部分节点失败 | 分别展示失败原因和其他节点结果       |
| SSH 断线     | 显示连接及远端任务状态未知，重连核对 |
| 用户停止     | 仅中断本任务，确认后显示已停止       |
| 关闭项目窗口 | 清理所属订阅与任务，保留其他窗口连接 |

## 所需条件

参见[连接说明](connections.md)与[Arthas 接入](arthas.md)。APP 不应自动扩大服务器权限，也不能假定日志权限等于诊断权限。
