# Docker 容器与日志

## 容器发现

在项目所选服务器上读取 `docker ps` 的容器 ID、名称、镜像和状态，根据已有标签或命名规则提出服务归组，再由用户确认。不要求为了发现能力先修改所有部署。

只读取必要元数据，不将完整 `docker inspect` 环境变量、挂载秘密或无关业务配置保存到 APP。

容器名称用于展示和匹配，远程任务应绑定服务器和容器 ID，并检查运行状态、启动时间及 JVM 启动身份。容器重建或重启后重新确认，不沿用旧诊断会话。

## 日志模式

以下命令展示语义，CONTAINER_ID、N、TIME 都是占位符。

| 模式             | 命令示意                                                      |
| ---------------- | ------------------------------------------------------------- |
| 只看新日志，默认 | `docker logs --follow --tail 0 --timestamps CONTAINER_ID`     |
| 最近 N 行并跟随  | `docker logs --follow --tail N --timestamps CONTAINER_ID`     |
| 指定时间并跟随   | `docker logs --follow --since TIME --timestamps CONTAINER_ID` |

不带 `--tail` 的 `docker logs -f` 会先输出 Docker 当前保留的历史内容，再跟随新日志。界面要明确区分，避免误把它当作只看新增。

N 和时间采用明确类型，目标容器来自已核对实例。通过 shell 执行时需要正确引用参数，不能把任意输入直接拼接成命令。实际日志驱动、轮转和保留时间会影响可查询范围。

## 合并与显示

每条输出带所属项目、环境、服务、实例和服务器；能区分时保留 stdout/stderr 来源。PTY 可能合并输出流，不得伪造精确来源。

使用 Docker 时间帮助按窗口合并，保留原始业务文本；多台服务器时钟可能不一致，因此不承诺严格全序。异常堆栈按实例组装，不能把其他节点的行混入同一异常。

`--tail N` 是 Docker 行数，不是 N 条完整业务事件。级别和 traceId 解析依赖实际日志格式，不应把无法解析的日志丢弃。

## 生命周期与容量

- 仅订阅当前查看或明确保持的日志源。
- 暂停显示只暂停界面推进，停止订阅才结束本次远程日志通道。
- 本地缓冲、推送批次和渲染列表有界；具体参数在日志量验证后确定并记录。
- 容器重建、通道中断和错误输出展示为明确状态，不静默切换到其他同名容器。
- 本地未保留的内容不能假称可全文查询；历史查询后续可复用已有 SLS。
