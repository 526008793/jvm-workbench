# Docker 容器与日志

## 容器发现

在项目所选服务器上读取 `docker ps` 的容器 ID、名称、镜像和状态，根据已有标签或命名规则提出服务归组，再由用户确认。不要求为了发现能力先修改所有部署。

只读取必要元数据，不将完整 `docker inspect` 环境变量、挂载秘密或无关业务配置保存到 APP。

0.3.18发现结果可点击“关闭列表”收起，再点击“显示容器列表”展开缓存结果；切换服务器或环境会清除旧列表，再次发现会重新读取。

容器名称用于展示和匹配，远程任务应绑定服务器和容器 ID，并检查运行状态、启动时间及 JVM 启动身份。容器重建或重启后重新确认，不沿用旧诊断会话。

## 日志模式

以下命令展示语义，CONTAINER_ID、N、TIME 都是占位符。

| 模式               | 命令示意                                                          |
| ------------------ | ----------------------------------------------------------------- |
| 只看新日志，默认   | `docker logs --follow --tail 0 --timestamps CONTAINER_ID`         |
| 最近 N 行并跟随    | `docker logs --follow --tail N --timestamps CONTAINER_ID`         |
| 最近一段时间并跟随 | `docker logs --follow --since TIME --timestamps CONTAINER_ID`     |
| 自定义开始并跟随   | `docker logs --follow --since START --timestamps CONTAINER_ID`    |
| 固定时间段         | `docker logs --since START --until END --timestamps CONTAINER_ID` |

“最近一段时间”可选5/10/30分钟或1/6/24小时。“自定义时间”通过日期时间控件选择，按本机时区换算为UTC后发送，避免服务器时区不同造成偏移。开始时间必填；结束时间选填且必须晚于开始时间。留空结束时间持续跟随，填写后仅读取固定时间段并自动结束；修改范围后需停止所选实例再重新开始，不会修改运行中的命令。

不带 `--tail` 的 `docker logs -f` 会先输出 Docker 当前保留的历史内容，再跟随新日志。界面要明确区分，避免误把它当作只看新增。

N 和时间采用明确类型，目标容器来自已核对实例。通过 shell 执行时需要正确引用参数，不能把任意输入直接拼接成命令。实际日志驱动、轮转和保留时间会影响可查询范围。

## 合并与显示

每条输出带所属项目、环境、服务、实例和服务器；能区分时保留 stdout/stderr 来源。PTY 可能合并输出流，不得伪造精确来源。

使用 Docker 时间帮助按窗口合并，保留原始业务文本；多台服务器时钟可能不一致，因此不承诺严格全序。异常堆栈按实例组装，不能把其他节点的行混入同一异常。

`--tail N` 是 Docker 行数，不是 N 条完整业务事件。级别和 traceId 解析依赖实际日志格式，不应把无法解析的日志丢弃。

## 生命周期与容量

- 仅订阅当前查看或明确保持的日志源。
- 暂停显示只暂停界面推进，停止订阅才结束本次远程日志通道。
- 本地缓冲、推送批次和渲染列表有界；具体参数在日志量验证后确定并记录。
- 容器重建、通道中断和错误输出展示为明确状态，不静默切换到其他同名容器。
- 本地未保留的内容不能假称可全文查询；历史查询后续可复用已有 SLS。

## 当前状态

0.2.0 已实现 docker ps 容器发现、手动关联、启动前 inspect 绑定容器 ID/StartedAt、多实例日志通道、来源标记、关键词过滤、暂停显示与停止。界面保留最近 2000 条显示记录；高输出时释放显示缓存并给出提示，原始日志仍以 Docker/SLS 为准。Java多行日志按应用日志头组装显示，超长记录分段显示，未实现堆栈折叠。验收要求见[验证计划](testing.md)。

## 当前通道与停止

直连 SSH 使用非 PTY exec，可标记 stdout/stderr；JumpServer 使用人工确认后的 PTY，因此只标记 pty，不伪造两路来源。日志数据批量推送到工作区，按 Docker 时间辅助排序，多节点不承诺严格全序。

暂停显示仍接收数据，停止会请求中断日志命令。收到远端结束状态才标为已停止；没有确认则显示状态未知。切换服务保留后台订阅，切换环境会停止旧环境订阅，断开、窗口重载或关闭释放所属连接。

不会自动切到新同名容器；容器重建或重启后需重新开始订阅，重新核对身份。当前仅在隔离 SSH 服务模拟 Docker CLI 响应验证，真实引擎和日志驱动需进一步联调。

## 多服务后台与合并查看

0.3.4切换服务只切换显示和实例选择，不停止后台任务；每条输出携带serviceId，以服务/服务器/容器显示来源。启动当前服务只清理该服务旧显示，保留其他服务缓存；本环境总显示缓存为最近2000条记录。合并开关可同屏查看环境内已订阅服务，筛选支持服务名。停止/清空按当前视图范围，环境切换停止旧环境订阅。

0.3.18未合并时只能单选当前服务的一个实例，显示/停止/清空均限定所选实例；开启合并才允许勾选多个实例，并同屏显示本环境已订阅服务。开始日志只启动当前服务所选实例、只清理所选实例旧显示。切换实例或关闭合并保留其他后台日志。底部重复实例展示已移除，容器映射及删除服务在“编辑服务”中操作。

不同JumpServer目标应使用不同目标配置及独立PTY，可以复用同一堡垒机认证。一条终端退出A再选B，不会保留A的运行上下文，也不能把两次发现的容器都当作同一目标。

## 停止后的目标状态

0.3.5在独立POSIX子shell中安装INT处理，再执行日志命令；Ctrl+C后由子shell回传退出标记，父层目标终端保持可用。重复的停止请求共用同一个进行中的操作，避免第二次Ctrl+C打到已经回到命令提示符的目标终端。

JumpServer停止等待最多5秒接收远端确认。收到当前命令的结束标记后显示已停止，连接继续保持已确认目标，可直接再次开始日志。实际未转发中断、连接丢失或超过等待窗口仍无退出确认时，显示未知并要求重新确认目标，不把未确认状态伪装为已停止。

## 多行 SQL 与异常记录

0.3.7按Java/Spring常见的“应用日期时间 + 日志级别”识别新记录（级别前可有线程名）。同一任务、同一输出流中，后续没有新日志头的行追加到当前记录，SQL正文、分隔线、空行及异常堆栈作为整体显示。不按Docker时间戳的纳秒差或推送批次拆分业务事件。

Docker添加的时间前缀保留为元数据，按首行时间对整条记录辅助排序，正文保留应用原文。续行即使分多批到达，也实时更新相同记录；关键词命中续行时显示整条，暂停期间保持之前的快照。不同实例或stdout/stderr/pty互相隔离；PTY本身无法区分stdout/stderr时仍只标记pty。

尚未遇到Java日志头的普通输出逐行显示；不保证识别任意自定义格式。沿用65536字符的长文本分段边界，超长事件会分段保留而不截断；停止时刷新尚未换行的末尾内容。`--tail N`仍表示Docker物理行数，历史起点可能位于一条业务日志中间。
