# 产品需求

## 定位

为管理多个 Java 微服务项目的开发和运维人员提供本地桌面工作台，统一 Docker 日志和按需 Arthas 诊断。产品能力尚未实现，本文为首期开发基线。

## 使用场景

- 项目 A 经 JumpServer 连接多台服务器，项目 B 直接 SSH，两个项目窗口并排查看。
- 一个服务分布于多个服务器，选择服务后合并查看所选实例的日志。
- 输入方法名并确认实际候选，在一个或多个实例上观察慢调用、参数或异常。
- 切换服务时仍能找到运行中的诊断任务；关闭一个工作区不影响其他工作区。

## 首期范围

| 领域   | 需求                                                        |
| ------ | ----------------------------------------------------------- |
| 工作区 | 项目管理、多窗口、环境选择、服务与实例导航                  |
| 连接   | SSH 密码/私钥，JumpServer SSH 交互认证、MFA 和资产选择      |
| 容器   | 读取 Docker 容器信息，确认服务归组，跟踪容器与进程启动代次  |
| 日志   | 只看新日志、最近 N 行、按时间、所选实例合并、筛选及来源标识 |
| 诊断   | 方法候选、ClassLoader、常用命令模板、内嵌终端               |
| 任务   | 所选实例独立状态、持续结果、停止、断线状态核对              |
| 平台   | macOS 首发，最低系统版本和芯片支持待构建验证后公布          |

## 关键业务规则

1. 连接方式属于服务器配置，同一项目可混用直连 SSH 和 JumpServer。
2. 服务名和容器名不是全局唯一标识，所有操作绑定项目和环境。
3. 选择“全部实例”只操作当前已选服务的实例，不等于全部项目或全部服务器。
4. 多实例任务允许部分成功，结果和错误必须分别标明来源。
5. 方法名只是搜索入口，同名方法、重载及 ClassLoader 需要明确匹配范围。
6. 请求提交、类增强成功、方法被调用和命令结束是不同状态。
7. 用户停止当前任务不应关闭整个 Arthas 或重置其他用户的增强。
8. 窗口关闭清理自身任务，不能把共享连接的其他使用者一起断开。

## 后续范围

SLS 历史日志查询、可获得结构化数据时的耗时树、更多发现能力以及 Windows。是否需要集中控制服务由实际协作需求决定。

## 首期之外

不实现新的日志存储平台、完整 APM、流量重放、在线代码修改或通用 Kubernetes 运维平台。Docker 之外的部署适配需另行定义需求。

## 验收

验收以[验证计划](testing.md)中的实际行为为准；未完成接入测试前，不承诺任意 JumpServer 版本、MFA 复用或目标镜像均兼容。
