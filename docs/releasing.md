# 发布流程

## 当前状态

当前没有应用发布、安装包、签名配置或应用构建工作流。`package.json` 的 0.0.0 是仓库基础版本，不代表已发布产品。本文件是后续发布执行准则。

## 应用发布前

1. 确认待发布版本的真实功能与已验证环境，更新 README、路线图和更新日志。
2. 锁定运行时依赖及 Arthas 配套版本，检查第三方 LICENSE/NOTICE 和校验信息。
3. 完成对应平台构建、安装、启动、卸载及核心接入验证。
4. 确认构建物不含开发配置、真实地址、日志、凭据或调试秘密。
5. 将平台、芯片架构、最低系统要求、已知限制和升级方式写入发布说明。

## macOS

计划使用 electron-builder。最低系统版本、arm64/x64 支持和产物格式必须由实际构建验证后确定。正式面向普通用户的发布需要准备 Apple Developer 签名和公证，相关凭据只保存在受保护的构建环境中。

未签名测试构建应明确标记，不能把它描述为已经签名公证的正式安装包。需要人工确认的系统安全提示由用户自行判断，不在工具中自动绕过。

## Windows

在 Windows 迭代阶段补充系统凭据、路径、SSH 行为和签名验证。Mac 通过不等于 Windows 可发布，不先生成名义上的 Windows 下载条目。

## GitHub Release

只有真实构建和验收通过后创建版本 tag 和 Release，附准确的产物清单、SHA-256 校验和、版本变化及限制。不自动将任意 main 提交发布给用户，首期也不实现自动更新服务。

当前 CI 只验证文档；发布流水线随实际应用代码和签名条件加入。
